# Technical writing

Write for a tired engineer who needs the correct answer on the first read.

## Pick the document mode

Use one dominant mode per document:

- Tutorial. Teach by building, with visible results after each step.
- How-to. Give competent readers the steps to achieve one goal.
- Reference. State complete facts, options, limits, and errors for lookup.
- Explanation. Explain one bounded topic, its constraints, choices, and alternatives.

Split and link when modes conflict.

## Sentence rules

- Use the real symbol, path, flag, command, or UI label.
- Address the reader as "you" when giving instructions.
- Put conditions before actions.
- Use commands for procedures and present tense for facts.
- Keep one instruction or thought per sentence.
- Prefer active voice and everyday words.
- Keep modifiers such as "only" next to the words they modify.
- Give pronouns one clear referent. Repeat the noun when needed.
- Use numbered lists for sequences and bullets for unordered sets.
- Use sentence-case headings and descriptive link text.
- Include expected output and validation commands where readers need proof.
- Apply the `unslop` skill before finalizing.

Check every path, command, count, and generated tree against the current artifact.
